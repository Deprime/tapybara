Монорепо на Bun workspaces: SvelteKit (SPA) + Hono-сервер, который отдаёт фронт и REST API.

## Структура

```
capyberries.local/
├── package.json            # workspaces: ["apps/*", "packages/*"]
├── .gitignore, README.md
├── packages/
│   └── shared/             # Zod-схемы API-контрактов + выведенные TS-типы
│       ├── package.json (tsconfig, zod)
│       └── src/index.ts
└── apps/
    ├── web/                # SvelteKit, TypeScript, Tailwind, adapter-static (SPA mode)
    └── server/             # Hono на Bun: /api/* + static из ../web/build
```

## apps/web (SvelteKit SPA)
- `npx sv create`-эквивалент вручную: sveltekit + vite + tailwind (v4, `@tailwindcss/vite`), TypeScript.
- `svelte.config.js` — `adapter-static` с `fallback: 'index.html'` (SPA mode).
- `src/routes/+layout.ts`: `export const ssr = false; export const prerender = false;` — чистый CSR.
- `vite.config.ts`: dev-прокси `/api` → `http://localhost:3000`, чтобы в dev не было CORS.
- Демо-страница `+page.svelte`, которая делает fetch к `/api/health` и одному data-роуту — как рабочий пример связи.

## apps/server (Hono + Bun)
- `@hono/node-server` НЕ нужен — используем нативный `Bun.serve({ fetch: app.fetch, port: 3000 })`.
- Hono app:
  - `app.route('/api', apiRoutes)` — REST-роуты;
  - `app.use(serveStatic({ root: '../web/build' }))` + SPA-fallback на `index.html` для не-API роутов;
  - CORS-middleware (для dev-сценариев), `hono/logger`.
- Drizzle ORM + `mysql2` (drizzle-orm/mysql-core), конфиг подключения из `.env` (DATABASE_URL), `drizzle-kit` для миграций, `drizzle.config.ts`.
- Демо: схема одной таблицы (например `items`), CRUD `/api/items` с Zod-валидацией из `packages/shared`.
- `/api/health` — проверка живости + коннекта к БД.

## packages/shared
- Zod-схемы запросов/ответов (например `createItemSchema`, `itemSchema`), `type Item = z.infer<...>`.
- Оба приложения импортируют `@capyberries/shared` — единый контракт фронта и бэка.

## Скрипты и workflow
- Root `package.json`: `dev` (запуск обоих через `concurrently`: web на 5173 с прокси, server на 3000 с `bun --hot`), `build` (build web → server подхватывает статику).
- `.env.example` для сервера (DATABASE_URL, PORT).
- README с инструкциями по запуску и миграциям.

## Порядок работ
1. Скелет монорепо: root package.json, workspaces, .gitignore, git init.
2. `packages/shared` со схемами.
3. `apps/server`: Hono + Drizzle/MySQL + static-раздача + демо CRUD.
4. `apps/web`: SvelteKit SPA + Tailwind + демо-страница с запросами к API.
5. Связка: скрипты dev/build, прокси, README.
6. Проверка: `bun install`, билд обоих приложений, запуск сервера (БД может не быть — health-роут и фронт должны работать и без неё, демо-CRUD задокументировать).
